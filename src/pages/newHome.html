CORE PROTOCOL Feb 2026

Beamio Commerce Protocol (BCP) v3.2

The definitive technical guide to the Dual-Chain Hybrid Architecture (Settlement L2 + Data L1).

1. Executive Summary

Beamio Commerce Protocol (BCP) is a decentralized interaction standard engineered for the Agentic Economy. Version 3.2 formally establishes the "Dual-Chain Architecture," decoupling Value Settlement (Base L2) from Data Sovereignty (CoNET L1). This resolves the Web3 commercialization paradox: achieving financial-grade security while enabling zero-marginal-cost social interaction.

2. System Architecture

  • Chain A (Value): Base Mainnet (Ethereum L2). Handles USDC settlement and ERC-1155 Vouchers.
  • Chain B (Data): CoNET Blockchain (Layer 1). Handles Identity (@BeamioTag) and Social Graph storage with No Central Database.

3. Account Model

A tethered hybrid architecture delineating permission boundaries:

  • Main Account (Vault/EOA): Cold storage and L1 identity root.
  • Smart Consumption Account (Express Pay/AA): Programmable commercial wallet (ERC-4337) for high-frequency interaction. Logic Execution includes smart routing, discount computation, and Reserve Mechanism logic.

4. Core Protocol I: Atomic Asset Container (AAC)

BCP v3.2 redefines the transmission format of digital assets. Assets are no longer simple token streams but are encapsulated within "Containers" capable of full lifecycle management.

4.1 Core Mechanism: The Reserve Mechanism

  1. State Locking: Upon initiation of a distribution request, the contract triggers the Reserve function.
  2. Balance Deduction: The protocol logically deducts the corresponding assets from the "Available Balance" and flags them on-chain with an isReserved status.
  3. Deterministic Solvency: The locked assets guarantee 100% solvency when the recipient scans the code to claim.

4.2 Distribution Modes

  • Direct Gifting: Peer-to-Peer atomic transfers based on CoNET L1 @Beamio Tag.
  • Batch Gifting: A merchant creates a "Parent Container" containing N assets. Users scanning the code automatically claim a "Child Asset" via smart contract logic. This scenario replicates decentralized "Red Packets" (Lucky Money) or fixed-quota airdrops with O(1) complexity.

5. Core Protocol II: Identity & Social Sovereignty

5.1 Beamio Decentralized Identity (BDID)

Infrastructure: On-chain identity protocol based on CoNET L1. The @BeamioTag is a native asset on the CoNET chain, ensuring complete Censorship Resistance.

Zero-Knowledge Recovery

  • Mechanism: User private keys are sharded and encrypted across P2P network nodes.
  • Reconstruction: Users can reconstruct their private keys locally without centralized custody by providing a Recovery Code (high-entropy string) or @BeamioTag + Password (mnemonic credential).

5.2 The On-Chain Social Ledger

  • Storage: All social relationships (Follow/Following) and the Social Graph are stored on-chain on CoNET L1.
  • Assetization: Fan relationships are the merchant's on-chain assets; the platform cannot delete or ban them.
  • Zero-Cost: Leveraging the high performance of CoNET L1, high-frequency social interactions do not consume Base (ETH) Gas.

6. Core Protocol III: Smart Routing & Settlement

BCP provides an "Asset-Agnostic" payment experience, utilizing smart contracts to automatically determine the optimal payment path.

6.1 Cascading Settlement Stack

  1. Priority 1 (Liability Layer): Verification and deduction of Vouchers and Points (Merchant Liability).
  2. Priority 2 (Liquidity Layer): Deduction of USDC balance within the AA account.
  3. Priority 3 (Funding Layer): Automatic pulling of funds from the EOA (optional).

6.2 Hybrid Verification Gas Architecture

  • Facilitator (Off-chain Policy Engine): Real-time verification of business rules (e.g., Membership Tiers, Reserve Status).
  • Verifying Paymaster (On-chain Gas Contract): Verification of signatures and sponsorship of Gas fees.

7. Developer Interface

We provide a JSON-RPC ("The Truth") interface for direct blockchain communication and a Beamio SDK ("The Experience") for rapid integration. AI Agents can read on-chain data via LLM-standard Schemas.

8. Data Privacy & Communication

8.1 Wallet-to-Wallet Encrypted Chat

  • Infrastructure: Based on CoNET underlying communication protocol and DePIN network.
  • Routing: The Wallet Address serves as the routing identifier, enabling Peer-to-Peer (P2P) direct connection via the CoNET network.
  • Storage Strategy: The chat relationship is established on the CoNET chain, but the encrypted payload is stored on local devices or a decentralized storage layer. No content is stored on-chain to protect privacy.

Atomic Asset Container (AAC)

Bridging the gap between Stateless On-Chain Settlement and Stateful Off-Chain Commerce.

The "State Gap" Problem

Standard EVM asset definitions (ERC-20, ERC-721, ERC-1155) are architected for synchronous, atomic transfers where ownership is binary and instantaneous. However, real-world commerce—characterized by asynchronous distribution via QR codes, "Magic Links," or autonomous AI Agents—introduces a critical "State Gap."

In current paradigms, distributing an asset off-chain without a custodian creates a Race Condition (The Double-Spend Vulnerability): If a user generates a payment link for 100 USDC, the underlying assets remain liquid in the wallet until the moment of redemption. If the user spends those funds elsewhere before the recipient claims them, the transaction fails.

The Solution: isReserved Mechanism

The AAC implements a finite state machine within the user's ERC-4337 Smart Account. The core architectural innovation is the isReserved boolean state, enabling a non-custodial "Soft Lock" mechanism on the Base L2 settlement layer.

  1. State Locking: Upon the initialization of an off-chain distribution intent, the protocol triggers a UserOperation to toggle the asset state to Reserved.
  2. Logical Deduction: The specified assets are cryptographically deducted from the Available Balance and sequestered within the contract storage. While the assets do not leave the user's custody, they are rendered immutable for any purpose other than the specific authHash generated for the container.
  3. Solvency Guarantee: This mechanism ensures 100% Protocol-Level Solvency. The validity of the off-chain container is guaranteed regardless of distribution latency or endpoint multiplicity.

Polymorphic Distribution Strategies

The AAC standard supports polymorphic distribution logic to accommodate diverse commercial requirements:

  • Direct Atomic Transfer: Peer-to-peer asset transmission utilizing CoNET L1 identity resolution for address abstraction.
  • Batch Instantiation (1-to-N): The creation of a "Parent Container" capable of spawning multiple "Child Assets" upon claim. This architecture supports high-concurrency scenarios—such as mass coupon issuance or "Red Packet" airdrops—executed with O(1) complexity for the issuer, significantly reducing gas overhead.

Lifecycle State Machine

The AAC enforces a rigorous, unidirectional lifecycle to ensure data integrity across the Dual-Chain architecture:

  1. Initialized: Definition of asset parameters (Type, Value, TTL) and access control logic off-chain.
  2. Reserved: On-chain execution locks the asset; generation of the claimSecret (Zero-Knowledge Proof compatible).
  3. Redeemed: The recipient provides a valid cryptographic signature; the protocol executes the atomic transfer to the destination Smart Account.
  4. Rolled Back: Upon Time-To-Live (TTL) expiration or explicit revocation by the issuer, the state reverts, unlocking liquidity back to the issuer's Available Balance.

Agentic Interoperability

AAC serves as a Trust Primitive for AI Agents, allowing them to "reserve" budget for tasks (e.g., travel booking) with execution guarantees. This enables a Trustless Escrow environment where merchants can verify fund availability via the isReserved state before releasing goods or services.

HARDWARE Supplier Guide

Beamio Smart Card Specifications

Technical requirements for the Beamio High-End E-ink Smart Card (BCP v3.2 Compatible).

1. Physical & Mechanical Requirements

  • Dimensions: Standard ISO/IEC 7810 CR80 (85.60 x 53.98 mm).
  • Thickness: 0.84mm - 1.2mm (Flexible PCB integrated).
  • Material: High-grade PVC / Polycarbonate with customized full-color offset printing.
  • Durability: Water-resistant and bend-resistant for daily use in restaurant environments.

2. Display Module (E-ink)

  • Screen Type: Ultra-low power Electronic Paper Display (EPD).
  • Resolution: High-contrast, 180° viewing angle, sunlight-readable.
  • Active Area Options:
    • 0.96-inch: Optimized for Dynamic QR Code display only.
    • 2.13-inch: Multi-data display (QR Code + USDC Balance + Membership Status).
  • Refresh Rate: Full refresh in <1 second (optimized for payment speed).

3. Core Functional Requirements

  • Dynamic QR Code Generation: Supports TOTP (Time-based One-Time Password) logic. QR code auto-refreshes every 180 seconds (3 minutes) to align with Beamio security standards.
  • Asset Monitoring: Real-time display of USDC (Cash) and $CCSA (Vouchers) balances. Supports up to 3 distinct asset views via physical button toggle.
  • Internal Clock (RTC): Integrated Real-Time Clock for autonomous QR refreshing without a live internet connection.

4. Communication & Security Interfaces

  • NFC Interface (Primary):
    • Protocol: ISO/IEC 14443 Type A (NXP NTAG 424 DNA or compatible).
    • Features: Supports SUN (Secure Unique NFC) messages for encrypted authentication.
    • Compatibility: Seamless "Tap-to-Pay" with Beamio Merchant POS (Android/iOS/Tablet).
  • Bluetooth Interface (Optional): BLE 5.0: For synchronization with the Beamio Consumer App (Personal Edition).
  • Secure Element (SE):
    • Certification: EAL5+ / EAL6+ military-grade security chip.
    • Role: Encrypted storage of private key shards for the Express Pay (AA) Account.

5. Battery & Power Management

  • Battery Type: Ultra-thin flexible lithium-polymer battery.
  • Battery Life: Minimum 2 years based on 10 daily refreshes (E-ink consumes power only on refresh).
  • Charging: Non-rechargeable (standard) or Qi wireless charging (optional upgrade).

6. Software & Protocol Integration

  • Standard Compliance: ERC-4337 (Account Abstraction) compliant signing logic.
  • Account Binding: Direct tethering of chip UID to Base Mainnet smart contract addresses.
  • APDU Commands: Supports standard Smart Card Application Protocol Data Unit commands for custom Beamio logic execution.

About Beamio

Beamio is the financial operating system for the next generation of commerce.

We started with a simple observation: The gap between Web2 commerce (loyalty, vouchers, points) and Web3 liquidity (USDC, stablecoins) is artificially widened by complexity. Gas fees, seed phrases, and fragmented networks have kept billions of dollars in value trapped in silos.

Simultaneously, the rise of Artificial Intelligence created a new urgency. AI Agents are smart enough to work, but too "unbanked" to pay. They cannot read paper receipts, hold bank accounts, or execute transactions.

Beamio bridges these worlds. We built a dual-chain protocol that combines the settlement security of Ethereum (Base L2) with the data sovereignty of our own high-performance chain (CoNET L1). This allows us to offer Issuance as a Service to merchants today, while building the Payment Rails for AI Agents tomorrow.

Our Core Philosophy

  • USDC First: We prioritize stable value over volatile speculation.
  • Invisible Tech: Users shouldn't know they are using blockchain.
